# ECG Dataset Normalization Pipeline Blueprint

This blueprint defines how to normalize the three local ECG datasets into one training-ready format:

- `data/ptb-xl`
- `data/ecg-arrhythmia`
- `data/sph-ecg`

The blueprint does not force every dataset to look identical at the raw-file level. It defines dataset-specific adapters that produce one shared manifest and one shared signal contract for model training and validation.

## Pipeline Blueprint

Use a two-stage pipeline:

1. Build a normalized metadata manifest.
2. Load waveforms through dataset-specific adapters during preprocessing or training.

The manifest should be lightweight and should not duplicate waveform arrays. It should store paths, label mappings, sample counts, patient identifiers, split assignment, and enough provenance to reproduce preprocessing.

The first target should be 10-second ECG classification. For Apple Watch-style experiments, extract Lead I from the normalized 12-lead records and later aggregate multiple 10-second windows into a 30-second decision.

## Patient Identity Rules

The unified `patient_id` is generated by our pipeline, not copied directly from any source dataset. Generate one ID per unique patient identity, not one ID per ECG record. Use the lightweight Python `nanoid` package with size 8:

```python
from nanoid import generate

patient_id = generate(size=8)
```

The identity key is:

```text
original_source_dataset + original_patient_id
```

Every ECG record with the same identity key must reuse the same generated `patient_id`. This prevents collisions between datasets, preserves patient-level grouping for splits, and gives the training code one clean patient namespace. Keep `original_patient_id` so we can always trace a row back to the source dataset.

Use `split_group_id = patient_id` for v1. This makes patient-level split enforcement explicit without creating a second random namespace. If a future dataset exposes household, device, or session groupings that are stricter than patient identity, only then introduce a different `split_group_id`.

Compute the patient grouping fields after generating `patient_id`:

```text
patient_record_count = number of records with the same patient_id inside the source dataset
is_multi_record_patient = patient_record_count > 1
```

These fields are control fields for leakage prevention and split auditing. They are not model input features.

## Split Balance Rules

Patient-level separation prevents leakage, but it does not automatically make train, validation, and test clinically comparable. The final manifest builder must also check the proportion of normal-reference records and abnormal/cardiovascular-positive records in each split.

Do not force a 50/50 normal-vs-disease split by default. For validation and test, preserve the cleaned dataset prevalence as closely as possible so evaluation reflects the population represented by the source data. If the training loop later needs more positive examples, handle that with training-only sampling, class weights, or loss weights. Never rebalance validation or test by oversampling.

For each included ECG record, derive `split_balance_group` from `normalized_labels`:

| `split_balance_group` | Rule |
|---|---|
| `normal_or_sinus_reference` | Labels contain only `normal`, `sinus_rhythm`, and other explicitly accepted normal-reference rhythm labels |
| `abnormal_or_cvd_positive` | Labels contain at least one disease, abnormal rhythm, conduction, ischemia, infarction, hypertrophy, interval, axis, paced, preexcitation, early repolarization, or Brugada target |
| `mixed_normal_and_abnormal` | Labels contain both normal-reference and abnormal targets; treat this as abnormal for stratification but report it separately |

For patient-level splitting, derive the patient balance group from all records sharing the same `split_group_id`:

- If any record for the patient is `abnormal_or_cvd_positive` or `mixed_normal_and_abnormal`, the patient-level group is abnormal.
- Otherwise, the patient-level group is normal-reference.

Split assignment rules:

- PTB-XL should keep the official `strat_fold` split because it is already a dataset-provided stratified split.
- ECG Arrhythmia should use deterministic patient-level stratified splitting by `split_group_id` and patient balance group.
- SPH should keep the patient-aware split policy, then validate that normal/abnormal proportions remain acceptable after multi-record patients are assigned.

Split QA must output normal-vs-abnormal counts and percentages by dataset and split. As a v1 gate, the normal/abnormal percentage in `val` and `test` should stay within 2 absolute percentage points of the cleaned included records for that dataset when feasible. If patient grouping or small class counts make that impossible, keep patient separation first and write the imbalance into the split balance report.

Example:

| original_source_dataset | original_patient_id | record_id | patient_id |
|---|---|---|---|
| `ptb-xl` | `13619.0` | `17` | `Ab3_xY9Q` |
| `ptb-xl` | `13619.0` | `18` | `Ab3_xY9Q` |
| `sph-ecg` | `S00001` | `A00001` | `xA91_kLm` |
| `ecg-arrhythmia` | `ecg-arrhythmia:JS00001` | `JS00001` | `Q7pLz_2a` |

Because Nano ID is random, persist the mapping table and reuse it on later runs instead of regenerating IDs:

| Field | Meaning |
|---|---|
| `original_source_dataset` | `ptb-xl`, `ecg-arrhythmia`, or `sph-ecg` |
| `original_patient_id` | Source patient identifier |
| `patient_id` | Generated Nano ID, size 8 |
| `split_group_id` | Same value as `patient_id` for v1 patient-level splits |

## Shared Signal Contract

Adapters should expose a common loader interface:

```python
class DatasetAdapter:
    dataset: str

    def build_manifest(self) -> list[dict]:
        ...

    def load_signal(self, row: dict) -> Signal:
        ...
```

The loaded signal should use:

```python
Signal = {
    "values": np.ndarray,  # shape: (num_leads, num_samples)
    "sampling_rate_hz": int,
    "lead_order": list[str] | None,
    "lead_order_source": str | None,
}
```

Use `lead_order_source` as a single string, not an array. It describes where the lead order came from:

- `wfdb_header` for PTB-XL and ECG Arrhythmia when parsed from headers.
- `source_documentation` if confirmed from official dataset documentation.
- null when the lead order is unknown, such as current local SPH files before documentation confirmation.

For training, add a separate preprocessing step that converts native signals to the model input:

- select Lead I or all 12 leads
- resample to target rate, for example 250 Hz or 500 Hz
- crop, pad, or window to 10 seconds
- standardize amplitude consistently
- emit final tensor shape, for example `(1, 5000)` for Lead I at 500 Hz or `(12, 5000)` for 12-lead at 500 Hz

## Adapter: PTB-XL

Dataset root:

```text
data/ptb-xl
```

Important files:

- `ptbxl_database.csv`
- `scp_statements.csv`
- `records500/**`
- `.archive/records100/**`

Waveform design:

- Format: WFDB `.hea/.dat`
- Use `filename_hr` for 500 Hz records.
- `records100` has been moved to `.archive/records100`; do not use it for the normalization manifest.
- Use `filename_lr` only if a future low-rate experiment explicitly restores or reads from `.archive/records100`.
- Do not emit both `filename_lr` and `filename_hr` as separate manifest rows. They are two sampled versions of the same ECG record, not two different patients or recordings.
- Native shape: 12 leads x 5000 samples for high-rate records.
- Native duration: 10 seconds.
- Native lead order from headers: `I|II|III|AVR|AVL|AVF|V1|V2|V3|V4|V5|V6`.

Manifest parsing:

- `original_source_dataset`: `ptb-xl`
- `record_id`: `ecg_id`
- `original_patient_id`: source `patient_id`, preserving the CSV value before normalization
- `patient_id`: generated by our normalization pipeline with Nano ID size 8
- `patient_id_source`: `source_column`
- `split_group_id`: same value as generated `patient_id`
- `patient_record_count`: count of PTB-XL rows sharing this generated `patient_id`
- `is_multi_record_patient`: `patient_record_count > 1`
- `age_at_recording`, `sex`, `recorded_at`: `age`, `sex`, `recording_date`
- `source_path`: extensionless `filename_hr` loader base
- `source_header_path`: `filename_hr` with `.hea`
- `source_signal_path`: `filename_hr` with `.dat`
- `source_format`: `wfdb-dat`
- `lead_order_source`: `wfdb_header`
- `raw_labels`: parse `scp_codes` with `ast.literal_eval`, then serialize to JSON
- `raw_label_system`: `scp-ecg`
- `quality_flags`: collect `baseline_drift`, `static_noise`, `burst_noise`, `electrodes_problems`, `extra_beats`, `pacemaker`
- `split`: map `strat_fold` to `train`, `val`, and `test`
- `split_source`: `ptbxl_strat_fold`

Recommended split:

- folds 1-8: `train`
- fold 9: `val`
- fold 10: `test`

Label mapping:

- Join `scp_codes` against `scp_statements.csv`.
- Use `diagnostic_class` for broad PTB-XL classes: `NORM`, `MI`, `STTC`, `CD`, `HYP`.
- Preserve rhythm and form statements because they may map to MVP rhythm labels.

Known edge cases:

- `scp_codes` is a Python-literal dict string, not JSON.
- `patient_id` is stored as a float-like value in CSV.
- PTB-XL originally contains both `records100` and `records500` for every metadata row. Locally, `records100` is archived at `.archive/records100`; the normalization manifest must choose the 500 Hz `filename_hr` path from `records500` so the same ECG is not duplicated.
- Do not use `RECORDS` as the source of truth; use `ptbxl_database.csv` paths.

## Adapter: ECG Arrhythmia / Chapman-Ningbo

Dataset root:

```text
data/ecg-arrhythmia
```

Important files:

- `WFDBRecords/**`
- `ConditionNames_SNOMED-CT.csv`
- `derived/ConditionNames_SNOMED-CT_complete.csv`
- `RECORDS`

Waveform design:

- Format: WFDB-style `.hea/.mat`
- Path pattern: `WFDBRecords/<group>/<shard>/<record>.hea` and `.mat`
- Native shape: 12 leads x 5000 samples.
- Native sampling: 500 Hz.
- Native duration: 10 seconds.
- Lead order from normal headers: `I|II|III|aVR|aVL|aVF|V1|V2|V3|V4|V5|V6`.

Manifest parsing:

- `original_source_dataset`: `ecg-arrhythmia`
- Discover records by scanning `WFDBRecords/**/*.hea`.
- `record_id`: filename stem, such as `JS00001`.
- `original_patient_id`: `ecg-arrhythmia:{record_id}`, such as `ecg-arrhythmia:JS00001`.
- `patient_id`: generated by our normalization pipeline with Nano ID size 8
- `patient_id_source`: `record_id_matches_one_record_per_patient_dataset_description`.
- `split_group_id`: same value as generated `patient_id`
- `patient_record_count`: normally `1` under the one-record-per-patient identity rule
- `is_multi_record_patient`: normally `false`
- `source_path`: extensionless WFDB record base path
- `source_header_path`: `.hea` path
- `source_signal_path`: `.mat` path
- `source_format`: `wfdb-mat`
- `lead_order_source`: `wfdb_header`
- Parse metadata from `.hea` comment lines:
  - `#Age:`
  - `#Sex:`
  - `#Dx:`
  - `#Rx:`
  - `#Hx:`
  - `#Sx:`
- `raw_labels`: comma-separated SNOMED CT codes from `#Dx`
- `raw_label_system`: `snomed-ct`
- `quality_flags`: include header override metadata when `derived/header_overrides.csv` applies, otherwise null for now because local metadata does not expose real signal-quality flags
- `split`: null only in raw adapter drafts; final combined normalized manifest must assign `train`, `val`, or `test`
- `split_source`: null only before split assignment; final combined normalized manifest should use `generated_patient_hash_split_from_record_id`

Split strategy:

- No official train/validation/test split was found locally.
- Use deterministic patient-level splitting with the generated unified `patient_id`, derived from `original_patient_id = ecg-arrhythmia:{record_id}`.
- Mark `split_source` as `generated_patient_hash_split_from_record_id`.
- This is acceptable for this dataset because the PhysioNet page describes the database as 12-lead ECGs from 45,152 patients and describes one saved ECG file per subject.
- Local verification also matches that description:
  - `.hea` files: 45,152
  - `.mat` files: 45,152
  - unique `.hea` record IDs: 45,152
  - unique `.mat` record IDs: 45,152
  - missing `.mat` for `.hea`: 0
  - missing `.hea` for `.mat`: 0

Label mapping:

- Join SNOMED CT codes to `derived/ConditionNames_SNOMED-CT_complete.csv`.
- Keep original `ConditionNames_SNOMED-CT.csv` untouched as the downloaded source file.
- The derived complete mapping is built from the local file plus PhysioNet Challenge 2021 scored/unscored mapping files.
- The derived mapping covers all 94 SNOMED CT codes used in local `#Dx` headers and also preserves 4 local taxonomy codes that do not appear in records.
- Keep any future unmapped SNOMED codes in `raw_labels` and report them before using them as training targets.

Known edge cases:

- Local `.hea` files do not expose an explicit `Patient_ID` field. The patient ID decision depends on the PhysioNet dataset description plus the local one-record-per-ID count check.
- Headers contain more unique diagnosis codes than the original `ConditionNames_SNOMED-CT.csv` maps, so the normalization pipeline must use the derived complete mapping.
- A small number of headers are malformed but the `.mat` waveform files still appear to contain 12 x 5000 arrays.
- `Rx`, `Hx`, and `Sx` are currently all `Unknown` locally, so do not treat them as rich clinical features.

## Adapter: SPH-ECG

Dataset root:

```text
data/sph-ecg
```

Important files:

- `metadata.csv`
- `code.csv`
- `records/*.h5`
- `example-code.pdf`
- `rule.pdf`

Waveform design:

- Format: HDF5.
- Path pattern: `records/{ECG_ID}.h5`.
- Internal dataset key: `/ecg`.
- Native shape: 12 leads x `N` samples.
- Native dtype: `float16`.
- Native sampling: 500 Hz.
- Native duration: variable, approximately 10-56 seconds locally.
- Most records are 10 seconds, but do not assume fixed length.

SPH v1 duration policy:

- Keep records with duration `10`, `11`, or `12` seconds.
- Use exact 10-second records as-is.
- For 11- and 12-second records, crop the first 10 seconds: `ecg[:, :5000]`.
- Exclude records with duration `>= 13` seconds from training and validation for v1.
- Keep excluded `>= 13` second records in the audit files for a later windowing pipeline.
- Use exclusion reason `sph_duration_ge_13_sec`.
- Store preprocessing policy as `crop_first_10_seconds` for every SPH record with `N > 5000` that remains included.

Local SPH duration stats:

| Group | Records | Duration stats |
|---|---:|---|
| all SPH records | 25,770 | min 10 sec, median 10 sec, Q3 11 sec, p95 15 sec, max 56 sec |
| exact 10 sec | 18,842 | used as-is |
| 11-12 sec | 4,362 | included and cropped to first 10 sec |
| `>= 13` sec | 2,566 | excluded from v1 training/validation |

The `>= 13` second group is more abnormal and should not be deleted permanently:

| Label / group | Kept `<= 12` sec | Excluded `>= 13` sec |
|---|---:|---:|
| Normal ECG | 57.3% | 24.1% |
| Ventricular premature complex(es) | 2.6% | 17.8% |
| Atrial fibrillation | 1.7% | 11.1% |
| ST deviation | 6.4% | 13.0% |
| ST deviation with T-wave change | 3.4% | 10.8% |
| T-wave abnormality | 8.2% | 12.6% |

This policy trades about 10 percent of SPH records for a cleaner v1 fixed-window dataset. The excluded group should be recovered later with a proper multi-window strategy instead of discarded.

Manifest parsing:

- `original_source_dataset`: `sph-ecg`
- `record_id`: `ECG_ID`
- `original_patient_id`: source `Patient_ID`
- `patient_id`: generated by our normalization pipeline with Nano ID size 8
- `patient_id_source`: `source_column`
- `split_group_id`: same value as generated `patient_id`
- `patient_record_count`: count of SPH rows sharing this generated `patient_id`
- `is_multi_record_patient`: `patient_record_count > 1`
- `age_at_recording`, `sex`, `recorded_at`: `Age`, `Sex`, `Date`
- `source_path`: `records/{ECG_ID}.h5`
- `source_header_path`: null
- `source_signal_path`: `records/{ECG_ID}.h5`
- `source_format`: `hdf5`
- `signal_key`: `/ecg`
- `lead_order_source`: null until source documentation confirms the lead order
- `num_samples`: `N`
- `duration_sec`: `N / 500`
- `raw_labels`: parse `AHA_Code`
- `raw_label_system`: `aha`
- `quality_flags`: null initially unless signal quality indices are generated later
- `split`: generated from the documented patient-separated split recipe
- `split_source`: `sph_example_code_patient_split`

Split strategy:

Use the deterministic split described in the local example:

- 80 percent train, 20 percent test.
- Put every record from patients with multiple ECGs into test.
- Fill the rest of test from single-record patients with `random_state=73`.
- Ensure zero patient overlap between train and test.
- Create validation by taking a patient-level subset from the training patients.

Label mapping:

- Parse `AHA_Code` by splitting on `;`.
- Split modifier expressions on `+`.
- Keep primary diagnostic codes.
- Treat codes in the modifier range `200 <= code < 500` as modifiers, not primary labels.
- Join primary and modifier codes to `code.csv`.

Known edge cases:

- Lead order is not encoded in local HDF5 attrs or CSV files. Confirm from source documentation before assigning a named order.
- Records have variable duration. For v1, include 10-12 second records and crop included records longer than 10 seconds to the first 10 seconds. Exclude `>= 13` second records from training/validation until windowing is implemented.
- Some patients have multiple ECGs; splits must be patient-aware.

SPH cleaning priorities before normalization:

1. Add `duration_sec = N / 500` and `duration_policy`.
2. Mark `duration_policy = exact_10_seconds` when `N == 5000`.
3. Mark `duration_policy = crop_first_10_seconds` when `5000 < N <= 6000`.
4. Mark `include_for_training = false` and `exclusion_reason = sph_duration_ge_13_sec` when `N >= 6500`.
5. Confirm every included HDF5 file has `/ecg`, shape `(12, N)`, `N >= 5000`, and finite first-10-second values.
6. Join SPH `AHA_Code` atoms to `code.csv` and `label_mapping.csv`.
7. Apply label-quality exclusions after duration exclusions.
8. Generate SPH normalized manifest rows with source metadata, label audit fields, duration policy, and final inclusion status.

This duration policy does not require rerunning `label_mapping.csv` because label mapping is source-code-level taxonomy work. It does require rerunning the record-level audit or SPH manifest builder so record inclusion and exclusion counts reflect `sph_duration_ge_13_sec`.

## Label Mapping Sub-Pipeline

The three datasets use different classification systems, so label normalization must be its own sub-pipeline. Do not compare raw label codes directly across datasets. PTB-XL uses SCP-ECG labels, ECG Arrhythmia uses SNOMED CT codes, and SPH-ECG uses AHA-style numeric codes with modifiers.

The label sub-pipeline should produce four layers for every ECG record:

1. `raw_labels`: exact source label payload.
2. `source_label_atoms`: parsed atomic labels from the source payload.
3. `source_label_descriptions`: source labels joined against the source taxonomy.
4. `normalized_labels`: manually curated MVP labels shared across datasets.

Do not delete raw labels after mapping. Label mapping will change as the model scope becomes clearer.

### Label Inventory

| Dataset | Label source | Raw labels in records | Taxonomy coverage | Notes |
|---|---|---:|---|---|
| `ptb-xl` | `ptbxl_database.csv:scp_codes` + `scp_statements.csv` | 71 SCP labels | 71/71 covered | 44 diagnostic labels, 19 form labels, 12 rhythm labels; broad diagnostic classes are `NORM`, `MI`, `STTC`, `CD`, `HYP` |
| `ecg-arrhythmia` | `#Dx:` comments in `WFDBRecords/**/*.hea` + `derived/ConditionNames_SNOMED-CT_complete.csv` | 94 SNOMED CT codes | 94/94 covered by derived taxonomy | Original local taxonomy covers 51/94; derived mapping adds the 43 missing codes from PhysioNet Challenge 2021 mappings |
| `sph-ecg` | `metadata.csv:AHA_Code` + `code.csv` | 59 atomic labels after splitting `;` and `+` | 59/59 covered | 44 primary labels and 15 modifiers; 1,036 unique full record-level `AHA_Code` combinations |

Raw label overlap is limited because the code systems differ. Overlap should be measured only after mapping source labels into shared `normalized_labels`.

### Dataset-Specific Parsing Rules

PTB-XL:

- Parse `scp_codes` with `ast.literal_eval`.
- Treat dictionary keys as source label atoms.
- Join atoms to `scp_statements.csv`.
- Preserve the likelihood/confidence values from the dictionary in `raw_labels`.
- Use `diagnostic_class`, `diagnostic_subclass`, `form`, and `rhythm` columns to map into shared labels.

ECG Arrhythmia / Chapman-Ningbo:

- Parse labels from the `.hea` comment line starting with `#Dx:`.
- Split comma-separated SNOMED CT codes into source label atoms.
- Join atoms to `derived/ConditionNames_SNOMED-CT_complete.csv`.
- Emit any future unmapped SNOMED CT codes into an `unmapped_labels` report.
- Treat `ConditionNames_SNOMED-CT.csv` as the original downloaded mapping and the derived complete file as the pipeline mapping source.

SPH-ECG:

- Parse `AHA_Code` from `metadata.csv`.
- Split first on `;`.
- Split composite labels on `+`.
- Treat codes in the modifier range `200 <= code < 500` as modifiers.
- Join every atom to `code.csv`.
- Preserve both raw expressions such as `145+362` and parsed atoms such as `145`, `362`.

### Shared Mapping Targets

Start with broad labels where overlap is clinically clear:

| Normalized label | PTB-XL examples | ECG Arrhythmia examples | SPH-ECG examples |
|---|---|---|---|
| `normal` | `NORM` | none in current first-pass mapping; sinus rhythm is kept separate | `1` |
| `sinus_rhythm` | `SR` | `426783006` | none |

Mapping must be conservative:

- Map only high-confidence equivalent concepts.
- Prefer broad groups over overly specific disease labels.
- Do not map uncertain labels into positive disease targets.
- Keep modifiers separate from primary disease labels unless a mapping rule explicitly uses them.
- Keep an `unmapped_labels` report for every dataset.

### Record Exclusion Rules

Do not delete raw records when labels are questionable. Mark them in the normalized manifest and keep them in a record-level audit file.

Each record-level manifest row must include:

| Field | Meaning |
|---|---|
| `include_for_training` | `true` only when the record has at least one usable normalized label and no hard label-quality exclusion |
| `exclusion_reason` | Pipe-delimited reasons explaining why the record is excluded, or null/empty when included |
| `label_mapping_statuses` | JSON list of mapping statuses observed across the record's source label atoms |
| `label_review_flags` | JSON list of review flags observed across the record's source label atoms |

Hard exclusion reasons:

- `label_mapping_needs_review`: at least one source label has `mapping_status = needs_review`.
- `inactive_snomed_concept`: at least one source label has `review_flags` containing `inactive_snomed_concept` or `snomed_active = false`.
- `unmapped_label`: at least one source label atom does not exist in `label_mapping.csv`.
- `unknown_normalized_label`: at least one mapped normalized label is outside the approved MVP label list.
- `modifier_only_without_primary_label`: all source label atoms are modifier-only and no usable disease/rhythm label remains.
- `no_training_label`: after mapping and exclusions, the record has no usable normalized labels.
- `invalid_mapping_payload`: a mapping row has malformed JSON or another parse failure.
- `sph_duration_ge_13_sec`: SPH v1 duration policy excludes records with `N >= 6500` samples / duration `>= 13` seconds.

Do not exclude records only because they are `mapped_with_warnings`. Many of those rows are intentionally broad multi-label mappings, such as bundle branch block mapping to both `conduction_abnormality` and `bundle_branch_block`. Exclude only hard problems above.

## First Validation Checks

Before training, verify:

- every manifest row points to an existing waveform file
- every loaded waveform has expected shape and finite values
- every split has no patient overlap where patient IDs exist
- label prevalence is not wildly different from source expectations
- normal-vs-abnormal proportions are reported by dataset and split in `split_balance_report.csv`
- validation and test normal-vs-abnormal proportions stay close to each dataset's cleaned included-record prevalence, unless patient-level separation makes that impossible
- Lead I extraction uses the same lead index across datasets where lead order is known
- variable-length SPH records are handled consistently
- ECG Arrhythmia unmapped SNOMED codes are reported, not silently dropped
